Setting this up with SuiteCRM

One-time work by a SuiteCRM administrator. Until it is done, the add-on has nothing to sign in to.

  1. Create an OAuth2 client. In SuiteCRM go to Admin → OAuth2 Clients and Tokens → New Password Client. Name it something recognisable, such as Thunderbird.
    It must be a Password client. A Client Credentials client issues no refresh token, so you would be signed out every hour, and every email you filed would be attributed to one shared API user rather than to you.
  2. Set a generated secret, not one you thought of. Use generate beside the secret field in Connection above: it makes a 256-bit random value and copies it, ready to paste into SuiteCRM's Change Secret field.
    This matters more than it looks. SuiteCRM stores the secret as hash('sha256', $secret), one round of a fast hash, with no salt and no iterations. Against a copy of the database a memorable secret falls to a wordlist in seconds, and an unsalted digest can be looked up in a precomputed table. A random 256-bit value is immune to both however it is stored.
  3. Copy it before you save. SuiteCRM keeps only the hash, so it can never be shown again. copy, beside the field, puts it back on the clipboard at any time. If it is lost, edit the client and set a new one. Leaving the field blank keeps the existing secret rather than clearing it.
  4. Check the API keys exist (usually already done). SuiteCRM needs Api/V8/OAuth2/private.key and public.key, readable only by the web server user, and oauth2_encryption_key set in config.php.
  5. Fill in the Connection form above with your CRM address, the client id and secret, and your own CRM username and password. The address is detected automatically whether the API sits at /Api or /legacy/Api.
Why this uses OAuth2, and what it gains you

The usual way to connect a mail client to SuiteCRM is its legacy v4_1 endpoint, which means keeping your CRM password in plain text inside the Thunderbird profile, permanently. It has to, because logging in again is the only way to recover once the server expires the session. That is also why such a connection appears to drop you on an upgrade.

Here the password is used once, exchanged for tokens, and discarded. What is kept is a refresh token that is replaced every time it is used.

The practical gain is revocation without collateral damage: if a laptop goes missing, an administrator deletes that one token and Thunderbird is locked out at once. No password change, and nothing else you use is disturbed.

One honest limitation: this is OAuth2's password grant, not a browser redirect flow. SuiteCRM registers an authorization-code grant but ships no /authorize endpoint, so there is nothing to redirect to. Your password therefore still passes through the add-on once. It simply is not kept.

Behaviour

Attachments

Signature logos and pictures placed inside the text, as opposed to files the sender deliberately attached.

SuiteCRM's Documents module is searchable and versioned, which suits a contract or a quote. The default puts PDFs, Office files and spreadsheets there and everything else in Notes. A Document that cannot be created falls back to a Note rather than being lost.

SuiteCRM blocks certain extensions via upload_badext, including .html and .js. Without this, such attachments are reported as skipped.

In the message list

A badge on the button as you read: a count when the sender is in SuiteCRM, a dot when they are not. Costs one lookup per correspondent, cached for a few minutes.

Who the sender is in SuiteCRM, shown above the email itself, with a link straight to the record. Requires Thunderbird's permission to modify how messages are displayed.

Adds a SuiteCRM tag on success, so filed mail is coloured in the list and can be filtered or searched. Rename or recolour it in Thunderbird's own tag settings.

While composing

A strip at the top of the compose window, with a one-click Create Lead when they are not, at the moment that is cheap rather than something to remember afterwards.

After you send a message, it is filed against the recipient's existing CRM record. Nothing new is ever created: if the recipient is not in the CRM, nothing happens.

Adds a read-only SuiteCRM address book, so typing a name in To: finds Contacts and Leads from the CRM. It queries live and keeps no local copy, so nothing goes stale and nothing is stored on disk, but autocomplete needs the CRM to be reachable.

Case references

SuiteCRM stamps the case number into the subject of mail it sends about a Case, so a reply comes back still carrying it. When the subject contains one, that Case is offered first and pre-selected. This is right even when the sender matches no CRM record at all, which is exactly the situation an address lookup handles worst.

Dates

SuiteCRM orders activity timelines by when a record was created, so without this a message written weeks ago appears under today's date. With it on, the record carries the message's own send time and sits in the right place in the history. Thunderbird does not record when a message was read, only whether it has been, so that is not available as a choice.

Who the email is filed against

For a message you received, the sender is used by default. For a message you sent, the first To: recipient is used instead, since the sender there is you, which is no use to the CRM.

Change in the filing window lists the other people on the message so you can file against one of them instead. To: recipients come first, since they are who the message was addressed to; Cc: recipients follow as secondary. Only people sharing the target's email domain are grouped as colleagues, and your own addresses are never offered.

To: recipients are always offered. Turn this off to leave people who were merely copied in out of the list.

Interface language

Thunderbird's own language is used unless you choose one here. This settings page stays in English for now; the archiving window, the menu entries and the notifications are what change.

What is remembered on this computer

Two things are kept in your Thunderbird profile so they can be offered back to you: where mail from an address was filed last time, which is what the right-click menu and Alt+Shift+A file against, and the subject of each of the last 30 emails you filed, for the Recent list. Neither is sent anywhere. Both are bounded, and both go when the add-on is uninstalled.

Clearing costs you only the convenience: the menu stops naming a record until you file the next email from that address. Nothing in your CRM is touched.

Mail accounts

Which accounts the filing button should work in. Messages in any account left unticked are ignored, and the button reports that the account is not enabled.

    Troubleshooting

    Captures what the add-on does and every request it makes to your CRM, so a problem can be diagnosed. Leave it off for normal use. Passwords, secrets and tokens are never recorded; switching this off discards whatever was recorded.

    What the report contains

    Passwords, client secrets and access tokens are never recorded, so they cannot appear. Message subjects and bodies are never captured either. By default email addresses are masked (j***@acme.se) and your CRM host is replaced with <host>, so the report is safe to post publicly.

    Turn these on only when sending the report privately to someone you trust, because they make it identifying.

First public release. What it does
  • Files an email into an existing SuiteCRM Lead, Contact, Account or Target. One click searches all four at the same time for the sender's address, so there is no module to pick and no search to type.
  • Files a reply to case mail against the Case it belongs to. SuiteCRM stamps the case number into the subject of email it sends about a Case, so the reply comes back carrying it — and that works even when the sender matches no CRM record at all, which is where an address lookup is weakest.
  • Creates a Lead, or a Contact under an Account, when the sender is not in the CRM yet. The form is filled in from their signature block, the message headers and any attached vCard, all parsed locally. Guessed fields are marked for you to confirm.
  • Stores attachments as Notes or Documents, archives a whole conversation in one action, and dates the CRM record by when the message was sent so the activity timeline stays in order.
  • Turns an email into a Case, Opportunity, Meeting or follow-up Task linked to the record, offering only the kinds SuiteCRM will actually link.
  • Shows whether a correspondent is in the CRM while you read and while you compose, and tags archived mail in Thunderbird.
Ways in
  • The toolbar button, or right-click a message or a selection of them. The menu can open the archiving window, file straight against the record that sender's mail went to last time, or create a record. The middle entry names the actual record and hides itself when there is nothing remembered.
  • Keyboard shortcuts: Alt+Shift+S opens the archiving window, Alt+Shift+A files against the remembered record without opening anything. Both re-bindable in Thunderbird's own add-on shortcut settings.
  • The subject the CRM stores can be edited before filing, and Strip Re: removes stacked reply and forward prefixes in one go. The message in Thunderbird is never modified.
Signing in Uses the SuiteCRM V8 REST API with OAuth2. Your CRM password is exchanged once for tokens and never stored. Only a rotating refresh token is kept, so a Thunderbird upgrade does not sign you out, and an administrator can revoke access by deleting a single token. One OAuth2 client serves a whole organisation, so an administrator can export the connection settings — CRM address, client id and secret — to a file for colleagues. Each person still signs in with their own username and password. The file holds no token and no username, and importing fills the form rather than connecting, so nothing can silently repoint the add-on at another server. Fits your CRM and your role You can choose which modules are searched: fewer means faster lookups, and a customised SuiteCRM can add its own. What is offered depends on your own access — SuiteCRM reports the modules you may list and view, so you are never offered one you would be refused, and a colleague with a different role sees a different list. The CRM's own labels are used, so a custom module reads properly. What you need
  • Thunderbird 140 ESR or newer.
  • SuiteCRM 7 or 8 with the V8 REST API enabled.
  • A one-time OAuth2 Password client, created by a SuiteCRM administrator. The Preferences tab walks through it and includes a generator for the client secret.
Known limitation: this uses OAuth2's password grant rather than a browser redirect flow, because SuiteCRM registers an authorization-code grant but ships no /authorize endpoint. Your password therefore passes through the add-on once. It is not kept.

Testing this add-on requires a SuiteCRM instance. It cannot be exercised without one.

Requirements:
- SuiteCRM 7 or 8 with the V8 REST API enabled.
- An OAuth2 Password client, created by a SuiteCRM administrator under
  Admin > OAuth2 Clients and Tokens > New Password Client. Only that grant type
  issues a refresh token, which is what the add-on relies on.
- Setup steps are in the add-on's own Preferences tab under "How to set this up",
  and in docs/SETUP.md in the repository.

I can provide a test instance with synthetic data, plus credentials, on request.
Please ask here and I will add them to this field.

Source: https://github.com/njordium/thunderbird_suitecrm_archiver
MPL-2.0. No build step, no dependencies, nothing minified or bundled. The .xpi
contents match the repository file for file.

On the validation warnings: addons-linter validates against Firefox's schema, so
Thunderbird's own permissions (messagesRead, accountsRead, messagesUpdate,
addressBooks, messagesTags, messagesTagsList, compose) and APIs (messages.*,
accounts.*, messageDisplay.*, compose.*, addressBooks.provider) are reported as
unknown. All are valid per Thunderbird's schemas. Thunderbird's own webext-linter
reports no errors, warnings or info findings; what remains is manual-review items.

Data handling, in case it comes up: the add-on talks only to the CRM address the
user configures. It holds one optional host permission, for that host. No
third-party site is contacted, there is no telemetry, and no remote code is
loaded. The user's CRM password is exchanged once for tokens and never stored.
